# Checkpoint 105 Validation Tiers

Checkpoint 105 is a **technology-architecture documentation checkpoint**, not a simulation checkpoint.

## Required tier - Architecture Contract

Always run:

- native PowerShell dependency/parser precheck for the CP105 wrapper and contract;
- CP104 native-evidence provenance check;
- active Concept v0.7e and archive-continuity check;
- technology-family storyboard JSON/Markdown consistency checks;
- idea-register lifecycle/status and structural-role checks;
- cross-pollination/legacy-revival/reference-synthesis presence and authority checks;
- frozen technology-workbook and executable simulation/game-surface checks against CP104;
- exact repository-manifest validation.

## Simulation / calibration tier

**Not applicable to CP105.**

CP105 declares:

- numerical TL chart changed: `false`;
- simulation/calibration run: `false`;
- declared trials: `0`;
- Python runtime required: `false`;
- .NET build required: `false`.

Do not run historical Monte Carlo, Deep Calibration, or the standing permutation suite merely because those tools exist in the repository. CP104 remains the accepted numerical/simulation baseline.

## Promotion boundary

Passing CP105 validates the architecture documents and repository consistency only. It does not:

- assign a new component statistic;
- promote a Candidate to production;
- make an Exotic concept researchable;
- turn a provisional TL window into a locked unlock level;
- override later human review.
