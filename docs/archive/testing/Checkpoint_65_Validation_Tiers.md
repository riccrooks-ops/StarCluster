# Checkpoint 65 Validation Tiers

Checkpoint 65 keeps the scrubbed validation model used by Checkpoints 60-64. The normal acceptance suite runs repository/build/unit/core-regression gates plus only the new stochastic study under review.

## Must always run

The normal suite has **8 stages**. It retains deterministic/core TL1 checks, the frozen 35-Space construction envelope, resource semantics, and runner self-tests, while replacing the accepted Checkpoint 64 study with the current **54-variant bilateral finite-map tactical-geometry study**.

At 10,000 trials per variant the normal stochastic workload is **540,000 trials**.

## Deep Calibration

Deep Calibration is optional. It retains Checkpoint 64's accepted 90-variant study plus the earlier accepted sensor, power-doctrine, composed-build, and historical TL1 stochastic corpus. With Checkpoint 65 added, the expected deep suite is **24 stages / 1,404 Monte Carlo variants / 14,040,000 default trials**.

Deep Calibration is not required for Checkpoint 65 acceptance because finite-map movement order and tactical fuel are opt-in through the new study fields. Historical study documents omit those fields and retain their accepted scalar movement path.

## Release-gate boundary

Release gates verify finite-map identity, mirrored movement-order coverage, bilateral sensing, nonnegative/consistent fuel accounting, actual boundary exercise, missile travel bounds, and preserved 5-TP/FullVolleyFirst controls.

No win percentage, family ranking, sensor Space value, missile performance target, or movement-order advantage is a release gate. Contextual capabilities such as Energy APEN remain protected from premature retuning.
