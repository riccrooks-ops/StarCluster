# Checkpoint 73 Validation Tiers

## Must always run

The normal Checkpoint 73 acceptance path contains 11 stages. It performs repository/native-dependency checks, the clean warning-as-error .NET build, all unit tests, retained deterministic mechanics regression suites, the 924-row Sensor/EW foundation sweep, an **actual-consumer CP73 AI-doctrine preflight**, a **24-variant one-trial full-pipeline smoke**, the 24-variant / 240,000-trial substantive EW AI-doctrine study, retained resource semantics, and ScenarioRunner self-tests.

The preflight and smoke are mandatory before the substantive Monte Carlo stage. They validate registry binding, actual doctrine execution, evidence-output wiring, and full-pipeline safety; they are not balance evidence.

The substantive stage must write `ew-ai-doctrine-review.csv` plus a hash-linked `ai-doctrine-evidence-draft.json`. The draft records the registry version/hash, study result hash, declared dependencies, accepted baseline doctrine, experimental candidates, aggregate telemetry, and all 24 context results. **Promotion is never automatic.** Human review decides whether an experimental doctrine becomes accepted, rejected, or remains experimental.

## Deep Calibration

Deep Calibration remains opt-in. It retains the broader historical/current calibration corpus and substitutes the CP73 preflight/smoke/substantive stages for CP72's primary study. Default workload: 30 stages, 1,568 substantive Monte Carlo variants / 15,680,000 substantive trials, plus 24 smoke trials.

Do not run Deep Calibration merely because it exists. Run it when a declared doctrine dependency changes, when normal acceptance produces a specific reason to broaden diagnostics, or when another retained subsystem is materially affected.
