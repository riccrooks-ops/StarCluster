# Checkpoint 79 Validation Tiers

## Must always run

Checkpoint 79 changes the integrated-study consumer and executes the first Matrix-v1 TL2 Sensor/EW candidate study, so its normal acceptance includes both deterministic foundation coverage and the focused substantive Monte Carlo pass.

The release path must run repository/manifest and native-dependency validation, warning-as-error build and unit tests, deterministic moving-missile scenarios, TL1 Phase A/B, the 35-Space construction envelope, the accepted deterministic Sensor/EW foundation, the CP79 actual-consumer preflight, a 54-variant one-trial full-pipeline smoke, the 54-variant substantive TL2 Sensor/EW isolation, deterministic resource semantics, and ScenarioRunner self-tests.

CP79 release gates are **mechanical/semantic**, not target win-rate gates. They prove that the real consumer can bind asymmetric Sensor/EW profiles and normal EW ratings; that rating-2 power scales at the declared per-rating cost; that the expected Firm/Approximate relationships occur in fixed-range controls; and that degraded direct fire/missile boundaries remain intact. Win share, pacing, PDS opportunity cost, and candidate promotion remain human-review evidence.

The first isolation deliberately keeps the legacy TL2 Tactical Computer +12 targeting candidate, Sensor/EW overload changes, sensor-range changes, and EW efficiency changes out of the study. Sensor DR 1 and normal ECM/ECCM rating 2 remain candidate values until post-run review explicitly promotes or revises them.

## Deep Calibration

Deep Calibration remains opt-in and dependency-driven. It adds the retained historical stochastic corpus to the normal CP79 study. Do not run it merely because CP79 contains Monte Carlo; the focused normal study is already the substantive evidence required for this candidate. Use Deep Calibration only if normal acceptance exposes a broader regression or if a later decision intentionally requires comparison against historical stochastic studies.
