# Checkpoint 91 Validation Tiers

Checkpoint 91 establishes external reference-mining infrastructure and preserves the initial Spacedock design corpus. It changes documentation/reference metadata and checkpoint contracts only. It does **not** change gameplay, runtime code, tests, simulation definitions, the Game Concept, Technology Architecture Matrix, Component Catalog, AI doctrine, or standing permutation architecture.

## Must always run

- Native/archive pre-check, including the proven direct named-parameter checkpoint-wrapper call into `run_calibration_checkpoint.ps1`; splatted/positional wrapper forwarding is rejected before harness execution.
- Repository/manifest and accepted-CP90a provenance contracts.
- Warning-as-error native build and full unit-test project.
- Accepted deterministic mechanics stages.
- ScenarioRunner self-tests (56 expected from the unchanged CP90a implementation).
- Reference-mining structural contracts: six mined sources, 70 stable observations, 24 queued sources, source/transcript hashes, notes, lifecycle/disposition vocabulary, deduplication flags, and authority-boundary text.
- Frozen implementation/game-authority hashes proving CP90a gameplay/simulation bytes did not change.

The CP90a 432-variant / 4.32M-trial generalized screen is **not rerun** because Checkpoint 91 changes none of its declared dependencies. Its native acceptance and substantive summary hashes are embedded as provenance and the relevant implementation/study files remain hash-frozen.

## Deep Calibration

Deep Calibration is **not applicable** to Checkpoint 91. The deep definition intentionally runs the same deterministic acceptance workload and no Monte Carlo studies.

No mined observation is promoted automatically. Reference-mining status is organizational evidence only; human design discussion owns adoption into any gameplay or technology authority.
