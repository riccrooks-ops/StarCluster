# Checkpoint 81 Validation Tiers

## Must always run

Checkpoint 81 follows accepted Checkpoint 80 and revalidates the legacy TL2 Tactical Computer **+12 percentage-point ordinary-targeting candidate** inside the contemporary Sensor/EW environment. Normal acceptance therefore keeps the deterministic TL1 foundation, adds the actual-consumer preflight for the standing Technology Integration Permutation Suite, runs a 96-variant one-trial full-pipeline smoke, and then runs the substantive 96-variant paired study.

The release path must run repository/manifest and native-dependency validation, warning-as-error build and unit tests, deterministic moving-missile scenarios, TL1 Phase A/B, the 35-Space construction envelope, the accepted deterministic Sensor/EW foundation, CP81 actual-consumer preflight, one-trial full-pipeline smoke, the substantive CP81 study, deterministic resource semantics, and ScenarioRunner self-tests.

CP81 release gates remain **mechanical and semantic**. They prove exact permutation coverage, paired +10/+12 computer candidates, actual-consumer execution for both computer values, clean Firm-reference behavior, the contemporary DR1+ECCM1 path, the wide old-Sensor+ECCM2 path, the explicit -25 degraded-fire fallback, 5-TP isolation, Evasive Compensation held at zero, production exclusion, and outcome-review-only policy. A deterministic ScenarioRunner self-test separately proves that the +12 override changes ordinary targeting by +2 pp, preserves the PDS local base while increasing main-computer assistance by the same +2 pp, and does not change missile Guidance Computer accuracy. Combat outcomes and aggregate hit-chance deltas remain human-review evidence rather than target gates.

The normal study contains **96 substantive variants at 10,000 trials each (960,000 substantive trials)** plus 96 one-trial smoke executions. The 96 variants are 12 combat/geometry comparison groups x four EW packages x two Tactical Computer candidates. The +10 and +12 variants within each comparison group use the same comparison-group random salt so small computer deltas are evaluated on paired random streams.

Checkpoint 81 also establishes the first standing **Technology Integration Permutation Suite**. The suite declares reusable scenario axes and machine-readable coverage, but a checkpoint activates only the dependency-relevant submatrix needed for causal interpretation. CP81 does not automatically rerun every technology combination in the repository, and successful execution promotes nothing automatically.

## Deep Calibration

Deep Calibration remains opt-in and dependency-driven. It adds the retained historical stochastic corpus to the normal CP81 study: **33 stages, 1,694 substantive variants, 16,940,000 substantive trials, plus 150 one-trial smoke executions** at default settings.

Do not run Deep Calibration merely because CP81 uses Monte Carlo. The focused normal study is the evidence required for the current Tactical Computer/EW integration question. Use Deep Calibration only if normal acceptance exposes a broader regression or a later design decision deliberately changes a dependency shared with the historical stochastic corpus.
