# Checkpoint 89 Validation Tiers

## Must run

Checkpoint 89 is a documentation/repository consolidation pass. Native acceptance must run repository/dependency contracts, warning-as-error build, the full test project, retained deterministic/mechanics stages, and ScenarioRunner self-tests.

The repository contract must verify:

- a single active Concept (`v0.6z`) and the non-additive ECM/ECCM redundancy rule;
- a single obvious current component Installation Space/multiplicity authority (Matrix **Component Catalog** + machine catalog JSON);
- the active/archive documentation boundary and removal of the parallel `docs/checkpoints/` history tree;
- current AI, testing, technology, validation, and archive navigation;
- exact accepted CP88 provenance;
- no changes under `src/` or `tests/` relative to accepted CP88; and
- no active Python dependency in the native acceptance path.

There is no Monte Carlo balance study in CP89.

## Deep Calibration

Not required by default and intentionally adds no stochastic work. CP89 changes documentation/authority organization and an explicit construction/stacking rule that is not exercised by the current one-ECM/one-ECCM runtime envelope; it does not alter combat implementation or candidate statistics.
