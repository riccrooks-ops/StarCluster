# Checkpoint 104 Validation Tiers

Checkpoint 104 is the **targeted TL3 diagnostic-closure checkpoint** after native-accepted CP103. It changes no game-facing technology value.

## Tier 1 — repository and native mechanics

Must pass every normal acceptance run:

- final CP104 repository manifest and PowerShell syntax;
- pinned .NET SDK 8.0.423;
- warning-as-error `StarCluster.Calibration.sln` build;
- full xUnit regression suite (876 tests expected from accepted CP103 unless deliberately changed);
- retained deterministic moving-missile and TL1 Phase A/B mechanics corpora;
- accepted CP102 32-variant executable TL3 regression smoke;
- retained ScenarioRunner self-tests.

C#/Godot remains gameplay/mechanics authority.

## Tier 2 — Python research-engine contract

Must pass before CP104 Monte Carlo:

- CPython 3.13.x, stdlib-only environment;
- Python research unit tests, including CP103 regression and CP104 v1.3 exact-contract tests;
- 25-case deterministic C#/Python parity corpus;
- accepted CP103 v1.1 exact population validation remains reproducible;
- CP104 v1.3 strict schema/recipe validation: 124,002,900 declared raw states; 52 unique named legal builds; 128 logical pairings; 256 variants; 12 exact-fill / 14 near-fill / 26 underfilled builds;
- complete 256-variant one-trial smoke with zero trial errors.

## Tier 3 — CP104 substantive diagnostic

- 256 variants × 500 trials = **128,000 substantive trials**;
- zero trial errors;
- 64 normalized diagnostic comparisons:
  - 16 legacy-frontier-response;
  - 10 movement-order decomposition;
  - 22 Energy-synergy decomposition;
  - 14 power-hot-spot comparisons;
  - 2 self/symmetry controls;
- CP103 accepted statistical-bundle reweight analysis must consume the embedded accepted 1,152-row primary variants artifact and reproduce 240 four-variant statistical bundles / 96 population cells.

All outcome thresholds are **review-only**. There is no automatic technology promotion, rejection, or retuning gate.

## Tier 4 — higher-TL handoff gate

After CP104, the default next development phase is higher-TL basic subsystem-chart expansion. Additional TL3 simulation is allowed only if review identifies a concrete architectural defect that would undermine later cross-TL work. Ordinary matchup imbalance, build specialization, or opportunity-cost-bearing legacy viability is not sufficient reason to keep iterating TL3 indefinitely.

## Deep Calibration

No separate Deep Calibration is required. CP104's substantive workload is deliberately bounded and causally focused; the deep definition is an alias of the normal acceptance workload.
