# Checkpoint 124 — Executable Technology and Instrumentation Foundation

## Intent

Checkpoint 124 is **native accepted**. It converts accepted CP123 reference data into a reusable research catalog and analytical foundation and intentionally performs no substantive balance calibration.

## Required acceptance evidence

The checkpoint must prove:

- accepted CP123 native/reference provenance;
- production C#/Godot and C# ScenarioRunner scenario-definition surfaces remain byte-frozen;
- all 20 CP123 numerical families and 180 TL rows are executable/retrievable;
- exhaustive same-TL enumeration produces exactly 14,112 raw combinations and 9,427 legal builds with residual Space explicitly represented as mission/AUX fill;
- GP Missile is available TL1-TL9 and Swarmer TL2-TL9;
- duplicate same-type ECM/ECCM remains non-additive;
- 139/139 Python self-tests pass;
- 25/25 existing C#/Python research parity fixtures pass;
- 70/70 zero-weight pipeline smoke trials execute without trial errors;
- 47 raw telemetry metrics are present and all 9 deterministic instrumentation probes pass;
- 0 substantive Monte Carlo trials are run and `balanceValidated=false`.

## Non-goals

CP124 does not tune CP123 values, add a C# scenario, change production mechanics, model internal critical/subsystem damage in Python, or claim that Python Missile travel reproduces the production moving-target range-exhaustion model.

## Post-acceptance direction

CP124 closes the immediate instrumentation-foundation step. CP125 uses this catalog/build/telemetry spine for the pure-TL whole-ladder study; later mixed-/cross-TL work should reuse the same foundation unless a substantive study reveals a genuine measurement blocker.
